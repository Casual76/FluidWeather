## Stable A/B interface

A adds trailing `weatherBrief: WeatherBrief? = null` to HomeUiState and supplies the app singleton WeatherBriefService through HomeDependencies under `weatherBriefService`. A may add `weatherBriefUpdating: Boolean = false` if needed, but B does not require it. `rememberHomeState(deps, place, active: Boolean = true)` accepts a page-visibility flag; B calls with `active = !coveredByPage`. UI keeps reading existing state for all old detail tiles; the new primary rain/current panel reads state.weatherBrief.

The brief is location-specific and re-evaluated with the consumption clock while visible/resumed and on snapshot/data changes. A model-only deterministic result may appear immediately from validated available inputs, followed by bounded shared radar assessment. A place/point change clears old-context brief and prevents late results applying to another location or data revision. Same-place refresh may retain coherent existing data. Current temperature/kind from brief are preferred for the new compact current display; hourly fallback must be explicitly labeled as forecast/cached or left unknown, never silently presented as current.

B owns localized presentation, header/compact timeline, sky and motion. WeatherBrief remains unlocalized domain data. WET/DRY sourced only from model must be qualified as model/recent estimate; no-echo radar wording must not claim measured dry ground. UNCERTAIN/UNAVAILABLE are explicit. Arrival/end are approximate absolute instants with 10-minute radar precision, not precise countdown promises; expired estimates cannot persist as future. Age uses sourceTimestampMillis/effectiveInterval/downloadedAtMillis rather than evaluatedAtMillis or round fetch alone. Timeline gaps remain unknown. Primary text is directly visible, essential caveat/source is concise, details below remain available.

## Design and verification boundaries

Use current engine3.0.5 Fluid components/material/tokens, existing backdrop sources and adaptive quality. No dependency/engine upgrade, new glass shader or per-item full-screen capture. Read the Fluid Engine and Material3 Expressive skills plus relevant component references. The app's pinned Fluid conventions govern actual components/motion/navigation. Top hierarchy: compact location/current, main rain sentence, next transition with essential limit, compact next-hour evolution. Avoid a giant temperature that pushes the answer below the fold. Fixed overview/header must not be draggable or persisted as tile IDs.

Normalize stored duplicate/unknown IDs in the ordered catalog without dropping temporarily hidden known IDs (notably nowcast when viewing elsewhere/no sensor). Persist full normalized order, not the visibility-filtered list. Details stay accessible exactly through stable tile IDs and requestedWidget flow.

Meaningful tests cover data update/location cancellation/stale response/time expiry, order normalization/preservation, faithful localized wording for each evidence state, unknown timeline segments and overview accessibility/layout at normal and large font. Instrumented UI tests may use synthetic briefs; they do not prove rain accuracy. Parent captures actual phone/tablet UI through Device tools and checks differing states/reduced motion. Full TalkBack/200% and matched performance gates continue in F6/F7 if not yet proved. No field/performance approval is inferred here.
